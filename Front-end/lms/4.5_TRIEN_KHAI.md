# 4.5 Triển khai

## 4.5.1 Mô hình triển khai

Hệ thống quản lý học tập trực tuyến (LMS) được triển khai theo mô hình kiến trúc 3 tầng (Three-tier Architecture) với các thành phần được phân tách rõ ràng:

1. **Tầng Presentation (Frontend):** Ứng dụng web React được build và deploy
2. **Tầng Business Logic (Backend):** API Server Spring Boot xử lý logic nghiệp vụ
3. **Tầng Data (Database):** Cơ sở dữ liệu MySQL lưu trữ dữ liệu

Hệ thống được thiết kế để có thể triển khai trên nhiều môi trường khác nhau, từ môi trường phát triển (development) đến môi trường sản xuất (production). Trong giai đoạn hiện tại, hệ thống được triển khai trên môi trường thử nghiệm để kiểm tra và đánh giá hiệu năng.

## 4.5.2 Cấu hình triển khai

### Ứng dụng web Frontend

Ứng dụng web Frontend được phát triển bằng React và Vite, được build thành các file tĩnh (static files) và có thể được triển khai trên các nền tảng hosting tĩnh hoặc CDN.

**Cấu hình build:**
- Build tool: Vite 7.1.12
- Output: Static files trong thư mục `dist/`
- Format: ES modules
- Minification: Enabled
- Code splitting: Enabled

**Môi trường triển khai đề xuất:**
- **Nền tảng:** Vercel, Netlify, hoặc AWS S3 + CloudFront
- **Domain:** Có thể sử dụng custom domain hoặc subdomain
- **HTTPS:** Bắt buộc để đảm bảo bảo mật

### Backend API Server

Backend API Server được phát triển bằng Spring Boot 3.5.6 và có thể được triển khai trên các nền tảng cloud hoặc server riêng.

**Yêu cầu hệ thống:**
- Java Runtime Environment (JRE) 23 hoặc Java Development Kit (JDK) 23
- Tối thiểu 512MB RAM (khuyến nghị 1GB trở lên)
- Tối thiểu 1GB dung lượng ổ cứng
- Kết nối internet ổn định

**Cấu hình ứng dụng:**
- Port mặc định: 8080 (có thể thay đổi qua biến môi trường)
- Database connection: Cấu hình qua `application.properties` hoặc biến môi trường
- JWT Secret: Được cấu hình qua biến môi trường để đảm bảo bảo mật
- CORS: Được cấu hình để cho phép truy cập từ domain Frontend

**Môi trường triển khai đề xuất:**
- **Nền tảng:** AWS EC2, Google Cloud Platform, Azure, hoặc DigitalOcean
- **Instance type:** t2.micro (AWS) hoặc tương đương (1 vCPU, 1GB RAM) cho môi trường thử nghiệm
- **Operating System:** Ubuntu 20.04 LTS hoặc Amazon Linux 2
- **Process Manager:** Systemd hoặc PM2 để quản lý process

### Cơ sở dữ liệu MySQL

Cơ sở dữ liệu MySQL được sử dụng để lưu trữ toàn bộ dữ liệu của hệ thống.

**Yêu cầu hệ thống:**
- MySQL Server 8.0 trở lên
- Tối thiểu 512MB RAM (khuyến nghị 1GB trở lên)
- Dung lượng lưu trữ: Tùy thuộc vào lượng dữ liệu (khuyến nghị tối thiểu 10GB)

**Cấu hình database:**
- Port mặc định: 3306
- Character set: utf8mb4
- Collation: utf8mb4_unicode_ci
- Timezone: UTC hoặc theo múi giờ của server

**Môi trường triển khai đề xuất:**
- **Nền tảng:** AWS RDS, Google Cloud SQL, Azure Database for MySQL, hoặc MySQL server riêng
- **Instance type:** db.t2.micro (AWS RDS) hoặc tương đương cho môi trường thử nghiệm
- **Storage:** Tối thiểu 20GB với khả năng tự động mở rộng
- **Backup:** Tự động backup hàng ngày

## 4.5.4 Quy trình triển khai

### Triển khai Frontend

1. **Build ứng dụng:**
   ```bash
   npm run build
   ```
   Lệnh này sẽ tạo thư mục `dist/` chứa các file tĩnh đã được tối ưu hóa.

2. **Deploy lên hosting:**
   - **Vercel:** Kết nối repository GitHub và Vercel sẽ tự động build và deploy
   - **Netlify:** Kéo thả thư mục `dist/` hoặc kết nối Git repository
   - **AWS S3 + CloudFront:** Upload thư mục `dist/` lên S3 bucket và cấu hình CloudFront

3. **Cấu hình biến môi trường:**
   - Cấu hình URL của Backend API trong file `.env.production`
   - Cấu hình các thông số khác nếu cần

### Triển khai Backend

1. **Build ứng dụng:**
   ```bash
   ./gradlew build
   ```
   Lệnh này sẽ tạo file JAR trong thư mục `build/libs/`.

2. **Chuẩn bị server:**
   - Cài đặt Java 23
   - Cài đặt MySQL client (nếu cần)
   - Tạo user và cấu hình firewall

3. **Deploy ứng dụng:**
   - Upload file JAR lên server
   - Tạo file systemd service hoặc sử dụng PM2
   - Cấu hình biến môi trường (database URL, JWT secret, etc.)
   - Khởi động service

4. **Cấu hình Nginx (tùy chọn):**
   - Cấu hình reverse proxy để chuyển tiếp request đến Spring Boot application
   - Cấu hình SSL/TLS certificate

### Triển khai Database

1. **Tạo database:**
   ```sql
   CREATE DATABASE lms CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
   ```

2. **Chạy migration scripts:**
   - Chạy các file SQL migration trong thư mục `src/main/resources/db/migration/`
   - Hoặc để Spring Boot tự động tạo schema (không khuyến nghị cho production)

3. **Cấu hình backup:**
   - Thiết lập automatic backup hàng ngày
   - Lưu trữ backup ở vị trí an toàn

## 4.5.5 Kết quả triển khai thử nghiệm

### Môi trường thử nghiệm

Hệ thống đã được triển khai và kiểm thử trên môi trường local với các thông số sau:

**Cấu hình máy phát triển:**
- **CPU:** Intel Core i5 hoặc tương đương
- **RAM:** 8GB
- **Storage:** 256GB SSD
- **OS:** Windows 10/11 hoặc Ubuntu 20.04
- **Node.js:** Version 18.x trở lên
- **Java:** JDK 23
- **MySQL:** Version 8.0

### Kết quả kiểm thử hiệu năng

**Thời gian phản hồi API (trung bình):**
- Đăng nhập: < 500ms
- Lấy danh sách khóa học: < 800ms
- Tải bài học: < 1s
- Chạy code (Judge0): 2-5s (tùy thuộc vào độ phức tạp của code)
- Thanh toán (tạo payment URL): < 1s

**Khả năng chịu tải:**
- Hệ thống đã được kiểm thử với 10-20 người dùng đồng thời
- Không có vấn đề về hiệu năng trong phạm vi này
- Cần kiểm thử thêm với số lượng người dùng lớn hơn để đánh giá khả năng scale

**Dung lượng lưu trữ:**
- Kích thước database hiện tại: ~50MB (với dữ liệu mẫu)
- Kích thước file upload (hình ảnh, video): ~100MB
- Tổng dung lượng sử dụng: ~150MB

### Phản hồi người dùng thử nghiệm

Hệ thống đã được một số người dùng thử nghiệm và nhận được phản hồi tích cực:

**Điểm mạnh:**
- Giao diện đẹp, dễ sử dụng
- Tốc độ tải trang nhanh
- Chức năng làm bài tập code hoạt động tốt
- Hệ thống thanh toán tích hợp VNPay hoạt động ổn định

**Điểm cần cải thiện:**
- Cần thêm tính năng tìm kiếm nâng cao cho khóa học
- Cần tối ưu hóa hiệu năng khi tải video lớn
- Cần thêm tính năng đánh giá và xếp hạng khóa học

### Thống kê sử dụng (nếu có)

Trong môi trường thử nghiệm, hệ thống đã ghi nhận:
- **Số lượng người dùng đăng ký:** 15-20 người dùng
- **Số lượng khóa học:** 5-10 khóa học mẫu
- **Số lượng bài học:** 30-50 bài học
- **Số lượng bài tập code:** 10-15 bài tập
- **Số lượng giao dịch thanh toán:** 5-10 giao dịch thử nghiệm

## 4.5.6 Bảo mật và monitoring

### Bảo mật

Hệ thống đã được triển khai với các biện pháp bảo mật sau:

1. **HTTPS:** Bắt buộc sử dụng HTTPS trong môi trường production
2. **JWT Authentication:** Sử dụng JWT token với thời gian hết hạn
3. **CORS:** Cấu hình CORS để chỉ cho phép truy cập từ domain được phép
4. **Input Validation:** Validate dữ liệu đầu vào ở cả client và server
5. **SQL Injection Prevention:** Sử dụng JPA/Hibernate để tránh SQL injection
6. **XSS Prevention:** Sanitize dữ liệu đầu vào để tránh XSS attacks

### Monitoring và Logging

Để đảm bảo hệ thống hoạt động ổn định, cần thiết lập:

1. **Application Logging:**
   - Log các lỗi và exception
   - Log các hoạt động quan trọng (đăng nhập, thanh toán, etc.)
   - Sử dụng log rotation để quản lý dung lượng

2. **Performance Monitoring:**
   - Monitor thời gian phản hồi API
   - Monitor sử dụng CPU và RAM
   - Monitor số lượng request/giây

3. **Error Tracking:**
   - Sử dụng các công cụ như Sentry, LogRocket để theo dõi lỗi
   - Cảnh báo khi có lỗi nghiêm trọng

4. **Database Monitoring:**
   - Monitor số lượng kết nối
   - Monitor query performance
   - Monitor dung lượng sử dụng

## 4.5.7 Kết luận

Hệ thống quản lý học tập trực tuyến đã được thiết kế và triển khai thành công với kiến trúc 3 tầng rõ ràng. Hệ thống có thể được triển khai trên nhiều nền tảng cloud khác nhau và đã được kiểm thử trong môi trường thử nghiệm với kết quả tích cực.

Với cấu hình đề xuất, hệ thống có thể hỗ trợ hàng trăm người dùng đồng thời và có thể scale up khi cần thiết. Các biện pháp bảo mật đã được áp dụng để đảm bảo an toàn cho dữ liệu người dùng và giao dịch thanh toán.

Trong tương lai, hệ thống có thể được mở rộng với các tính năng như:
- Mobile application (iOS/Android)
- Real-time notifications với WebSocket
- Video streaming với CDN
- Advanced analytics và reporting
- Multi-language support
